2OpenAPI: 요청과 응답 씨마스

API(Application Programming Interface)는 프로그램끼리 데이터를 주고받는 약속이고, 누구나 신청해서 쓸 수 있게 공개한 API를 OpenAPI라고 합니다. 공공데이터포털이나 서울 열린데이터광장 같은 곳에서 회원 가입 후 신청하면 인증키(API 키)를 받습니다. 인증키는 “누가 요청했는지” 확인하는 출입증이므로 비밀번호처럼 남에게 보여 주거나 공개 게시판·코드에 올리면 안 됩니다.

API 요청은 대부분 웹 주소(URL) 하나로 이루어집니다. 아래는 이 교재에서 만든 가상의 공공자전거 API 주소입니다.

① 기본 주소https://api.example.org/citybike/v1어느 서버의 어떤 API인지
② 서비스(자원)/stations어떤 데이터를 원하는지
③ 파라미터?key=…&type=json&start=1&end=5? 뒤에 이름=값을 &로 이어 조건을 전달
④ 응답상태 코드 + 데이터200은 성공, 4○○은 요청 쪽 잘못

실제 공공 API는 인증키·형식·범위를 주소의 경로 안에 넣는 방식(예: …/인증키/json/서비스명/1/5/)을 쓰기도 합니다. 모양은 달라도 ‘누가, 무엇을, 어떤 조건으로’ 요청하는지 담는다는 점은 같습니다. 어떤 방식인지는 각 API의 명세서(문서)를 읽어 확인합니다.

API 요청 URL 조립기 — 가상의 공공자전거 API

파라미터를 바꾸면 요청 주소가 조립되고, ‘요청 보내기’를 누르면 서버가 돌려줄 응답의 예시가 나타납니다. (실제 인터넷 요청은 보내지 않는 모의 실험입니다.)

응답 대기 중 
‘요청 보내기’를 눌러 보세요.

실험: ① 구를 ‘중구’로 고르면 주소의 글자가 어떻게 바뀌나요? ② 인증키를 지우고 요청해 보세요. ③ start=1, end=8처럼 범위를 넓히면? ④ 연속 요청 버튼을 눌러 보세요. 서버는 왜 이런 제한을 둘까요?

URL 인코딩 웹 주소에는 영문·숫자·일부 기호만 쓸 수 있어서 ‘중구’ 같은 한글이나 빈칸은 %EC%A4%91%EA%B5%AC처럼 바뀌어 전달됩니다. 이것을 URL 인코딩이라고 합니다. 파이썬의 urllib.parse.quote("중구")로 직접 바꿔 볼 수 있습니다.

3파이썬으로 JSON 응답 다루기 씨마스

API 응답으로 가장 많이 쓰이는 형식은 JSON입니다. {"이름": 값} 꼴의 묶음(객체)과 [ ] 목록(배열)이 겹겹이 들어 있는 반정형 데이터입니다. 실제 요청 코드는 requests.get(url) 한 줄이지만, 여기서는 인터넷 연결 없이 연습하도록 서버가 돌려준 응답 문자열을 미리 넣어 두었습니다. 한 번에 최대 5건만 주는 API라서 두 번에 나누어 받은 상황입니다.

결과를 보면 8개 대여소 중 중앙역 1번 출구(0.15), 중앙시장 입구(0.00), 서부버스터미널(0.10) 세 곳이 채움률 20% 미만입니다. 실제 공공자전거 운영 기관도 이런 실시간 데이터로 자전거를 트럭에 싣고 옮기는 ‘재배치’ 계획을 세웁니다.

4HTML 구조와 크롤링의 원리 YBM

웹 페이지는 HTML로 쓰여 있습니다. HTML은 <태그>내용</태그> 꼴의 요소가 상자 안에 상자가 들어가듯 겹쳐진 구조이고, class, id 같은 속성으로 요소에 이름표를 붙입니다. 크롤러는 ① 페이지를 내려받고 ② HTML 구조를 분석(파싱)해서 ③ 원하는 태그·속성의 내용만 뽑아 ④ 표로 저장합니다.

HTML에서 뽑은 값은 모두 글자(문자열)이므로 숫자로 계산하려면 astype(int)처럼 자료형을 바꾸어야 합니다. 이처럼 웹 수집 뒤에는 거의 항상 전처리가 뒤따릅니다. 실무에서는 BeautifulSoup 같은 라이브러리로 더 짧게 쓰지만 원리는 같습니다.

5크롤링 윤리: 할 수 있다 ≠ 해도 된다 씨마스

기술적으로 수집할 수 있다고 해서 모두 수집해도 되는 것은 아닙니다. 웹 데이터를 모으기 전에 다음 다섯 가지를 확인하세요.

📜 이용약관

사이트가 자동 수집을 금지하는지 확인한다. 금지된 수집은 법적 분쟁이 될 수 있다.

🤖 robots.txt

사이트 주소 뒤 /robots.txt에 운영자가 수집 로봇에게 허용·금지하는 경로를 적어 둔다. 반드시 따른다.

🔒 개인정보

이름·연락처·사진 등 개인을 알아볼 수 있는 정보는 공개되어 있어도 함부로 모으거나 다시 퍼뜨리지 않는다.

©️ 저작권

기사·글·이미지 원문을 통째로 복제해 공유하지 않는다. 출처를 밝히고 분석 결과 위주로 활용한다.

🐢 서버 배려

짧은 시간에 요청을 쏟아붓지 않는다. 요청 사이에 간격을 두고, 필요한 만큼만 수집한다.

robots.txt는 다음처럼 생겼습니다. User-agent는 대상 로봇, Disallow는 수집 금지 경로, Allow는 허용 경로, Crawl-delay는 요청 사이에 기다릴 초입니다. 파이썬의 urllib.robotparser로 규칙을 해석해 봅시다(이번에도 인터넷 없이 문자열로 연습합니다).

robots.txt에 허용되어 있어도 robots.txt는 운영자의 요청을 적은 약속일 뿐, 모든 수집을 허락한다는 보증서가 아닙니다. 허용된 경로라도 이용약관·개인정보·저작권 문제는 따로 확인해야 합니다. 학교 과제라면 공식 API나 공공 데이터 포털의 파일을 먼저 찾아보는 것이 가장 안전합니다.
토론 활동이 수집, 해도 될까? 씨마스

각 상황을 ⭕(해도 됨) / △(조건부) / ❌(하면 안 됨)으로 판단하고 근거를 쓰세요. 모둠 의견이 갈리면 어떤 조건에서 괜찮은지 토론해 보세요.

상황판단근거 (확인할 것)
① 공공데이터포털에서 인증키를 받아 우리 지역 대기 질 데이터를 1시간마다 받는다.
② 친구들의 SNS 공개 게시물에서 이름·사진·학교를 모아 ‘우리 학교 인기 순위’ 표를 만든다.
③ 뉴스 사이트의 기사 제목만 모아 단어 빈도를 분석하고 결과 그래프를 발표한다.
④ 공연 예매 사이트에 1초에 수백 번 요청하는 프로그램으로 표 판매 상황을 확인한다.
⑤ 내 인증키가 들어간 코드를 그대로 공개 코드 저장소에 올린다.
판단 예시 보기
① ⭕ 공식 API로 허용된 방법이다(요청 횟수 제한은 지킨다). ② ❌ 공개 게시물이라도 개인을 알아볼 수 있는 정보를 모아 순위를 매기는 것은 개인정보 침해이자 괴롭힘이 될 수 있다. ③ △ 이용약관·robots.txt가 허용하고, 기사 원문을 복제·배포하지 않으며 출처를 밝히면 가능하다. ④ ❌ 서버에 큰 부담을 주어 다른 이용자에게 피해를 주고 약관 위반 소지가 크다. ⑤ ❌ 인증키는 비밀번호와 같다. 코드에서 빼거나 별도 설정 파일로 관리한다.
지도 팁 확장 차시입니다. 실제 API 실습을 하려면 교사가 공공데이터포털에서 미리 인증키를 발급받아 두고, Colab 등에서 requests로 요청하게 할 수 있습니다(이 교재의 파이썬 셀은 브라우저에서 돌아가므로 외부 요청 대신 샘플 문자열을 씁니다). 학생 개인이 가입해 인증키를 받게 할 경우 개인정보 동의 절차와 연령 조건을 확인하세요. 비코딩 반은 스프레드시트의 IMPORTHTML·IMPORTXML 함수나 Orange의 JSON 불러오기로 같은 원리를 체험할 수 있습니다. 윤리 토론의 ③처럼 조건에 따라 판단이 갈리는 사례에서 ‘무엇을 확인하면 되는가’를 끌어내는 것이 핵심입니다.

📌 핵심 정리

  • API는 제공자가 정한 주소(기본 주소 + 서비스 + 파라미터)로 요청해 JSON·XML 같은 정리된 데이터를 받는 공식 통로이며, 인증키는 비밀번호처럼 관리한다.
  • JSON 응답은 json.loads로 파이썬 자료로 바꾼 뒤 pd.DataFrame으로 표를 만들어 분석한다.
  • 크롤링은 HTML을 파싱해 태그·속성을 길잡이로 필요한 내용을 뽑는 것이며, 뽑은 값은 전처리(자료형 변환 등)가 필요하다.
  • 웹 수집 전에는 이용약관·robots.txt·개인정보·저작권·서버 부담을 반드시 확인한다.
