생각 열기 수학 시험을 앞둔 두 친구가 있습니다. 민재는 문제집 50문제의 답을 통째로 외웠고, 서윤이는 풀이 원리를 이해하며 공부했습니다. 문제집을 다시 풀게 하면 민재가 100점, 서윤이가 90점입니다. 그런데 실제 시험에서는 숫자만 바뀐 새 문제가 나왔습니다. 누가 더 잘 볼까요? 모델도 똑같습니다. 이미 본 데이터(문제집)만 잘 맞히는 모델은 새 데이터(시험)에서 무너질 수 있습니다.
확장 차시 안내 이 차시는 훈련/테스트 분할(L29)과 의사결정트리(L37)를 간단히 안다고 가정합니다. 회귀 모델의 성능은 결정계수 R²로 비교합니다. R²는 ‘정확도’가 아니라, 평균값 하나로 예측할 때보다 오차를 얼마나 줄였는지를 나타내며(1에 가까울수록 좋음), 평균보다도 못한 모델이면 음수가 될 수도 있습니다.

1과대적합과 과소적합 공통

과소적합 (underfitting)

모델이 너무 단순해 데이터의 패턴조차 잡지 못함. 훈련 성능도 테스트 성능도 낮다. 예: 곡선 관계를 직선 하나로 설명

적절한 적합

핵심 패턴은 잡고 잡음은 무시함. 훈련 성능과 테스트 성능이 모두 괜찮고 차이가 작다.

과대적합 (overfitting)

훈련 데이터의 잡음까지 외움. 훈련 성능은 매우 높은데 테스트 성능은 낮다. 예: 답만 외운 민재

과대적합은 모델이 복잡할수록(트리가 깊을수록, 다항식 차수가 높을수록, k-NN의 k가 작을수록), 그리고 데이터가 적을수록 잘 일어납니다. 그래서 모델을 평가할 때는 반드시 학습에 쓰지 않은 데이터로 성능을 확인하고, 훈련 성능과 비교해야 합니다.

2데이터가 적으면 더 쉽게 외운다 삼양

bike.csv(가상의 공공자전거 1년 대여 기록)로 확인해 봅시다. 기온·습도·풍속·강수량·휴일로 하루 대여량을 예측하는 의사결정트리를 깊이 제한 없이 학습시키되, 훈련에 쓰는 날 수를 10일부터 늘려 갑니다. 테스트 데이터(110일)는 항상 같습니다.

깊이 제한이 없는 트리는 훈련 데이터를 모두 외워서 훈련 R²가 늘 1.000입니다. 하지만 10일만으로 학습하면 테스트 R²는 0.095에 불과합니다. 훈련 데이터를 30일, 100일, 255일로 늘리자 테스트 R²가 0.288 → 0.454 → 0.571로 올라갑니다. 데이터가 많을수록 우연한 잡음을 ‘규칙’으로 착각하기 어렵기 때문입니다.

3복잡도 고르기와 k-겹 교차 검증 삼양

이번에는 훈련 데이터 전체(255일)로 트리의 최대 깊이를 1부터 15까지 바꿔 봅니다.

깊이를 늘리면 훈련 R²는 0.519에서 0.999까지 계속 오르지만, 테스트 R²는 깊이 5에서 0.700으로 가장 높았다가 다시 떨어져 깊이 15에서는 0.580입니다. 깊이 1~2는 과소적합, 깊이 10 이상은 과대적합 구간입니다.

테스트 데이터로 깊이를 고르면 안 되는 이유 위 표를 보고 “테스트 R²가 가장 높은 깊이 5를 고르자”고 하면, 테스트 데이터를 모델 선택에 사용한 셈입니다. 그러면 테스트 데이터가 더 이상 ‘처음 보는 시험’이 아니어서, 최종 성능을 부풀리게 됩니다. 이것도 데이터 누수의 한 종류입니다. 모델의 설정(깊이, k 등)은 훈련 데이터 안에서 정하고, 테스트 데이터는 마지막에 딱 한 번만 씁니다.

그렇다면 훈련 데이터 안에서 어떻게 성능을 비교할까요? 훈련 데이터를 한 번만 나누면 어떤 날들이 검증용으로 뽑혔느냐에 따라 점수가 들쭉날쭉합니다. k-겹 교차 검증(k-fold cross validation)은 훈련 데이터를 k개 묶음(폴드)으로 나눈 뒤, 돌아가며 한 묶음씩 검증용으로 쓰고 나머지로 학습합니다. k번의 점수를 평균하면 운에 덜 좌우되는 성능 추정치를 얻습니다.

깊이 5의 다섯 폴드 점수는 0.617~0.762로 꽤 차이가 납니다. 검증 데이터를 한 번만 나눴다면 이 중 어느 값을 받았을지 모르는 셈입니다. 교차 검증 평균은 깊이 5에서 0.684로 가장 높으므로, 테스트 데이터를 보지 않고도 깊이 5를 고를 수 있습니다. 마지막으로 테스트 데이터로 한 번 평가한 결과는 0.700입니다.

4너무 좋은 결과를 의심하라: 데이터 누수 YBM 씨마스

데이터 누수(data leakage)는 예측하는 시점에는 알 수 없는 정보, 또는 테스트 데이터의 정보가 학습에 섞여 들어가는 것입니다. 누수가 있으면 평가 점수는 훌륭하지만 실제로 쓰면 형편없는 모델이 됩니다. 대표적인 경우는 다음과 같습니다.

  • 미래 정보를 입력으로 사용: 오늘 대여량을 예측하는데 ‘오늘 반납된 자전거 수’를 입력으로 쓰기 (반납량은 하루가 끝나야 알 수 있음)
  • 테스트 데이터로 전처리 기준 정하기: 전체 데이터의 평균·표준편차로 표준화한 뒤 나누기 → 훈련 데이터로만 기준을 정해야 함(파이프라인 사용)
  • 테스트 데이터로 모델 설정 고르기: 위에서 본 깊이 고르기 문제

반납량을 넣자 테스트 R²가 0.4048 → 0.9965로 치솟았습니다. 하지만 내일 대여량을 예측하려는 시점에 내일의 반납량은 알 수 없으므로 이 모델은 실제로 쓸 수 없습니다. 결과가 믿기 어려울 만큼 좋다면 먼저 누수를 의심해야 합니다.

지도 팁 도입의 ‘답 외우기 vs 원리 이해’ 비유를 위젯의 차수 9(훈련 오차 0, 테스트 오차 폭발)와 연결하면 과대적합 개념이 빠르게 잡힙니다. 교차 검증은 학생 25명을 5모둠으로 나눠 ‘한 모둠씩 돌아가며 시험 감독’을 하는 역할극으로 설명할 수 있습니다. Orange 학급은 Test and Score 위젯의 Cross validation(Number of folds)과 Test on train data 결과를 비교하게 합니다. 흔한 오개념: “훈련 점수가 높을수록 좋은 모델”, “교차 검증은 테스트 데이터를 여러 번 쓰는 것”(테스트 데이터는 따로 떼어 둠), “R²는 맞힌 비율(정확도)”.

📌 핵심 정리

  • 과소적합은 훈련·테스트 성능이 모두 낮고, 과대적합은 훈련 성능은 높은데 테스트 성능이 낮다.
  • 모델이 복잡할수록, 데이터가 적을수록 과대적합이 일어나기 쉽다 — 데이터를 늘리거나 복잡도를 줄인다.
  • k-겹 교차 검증은 훈련 데이터를 k묶음으로 나눠 돌아가며 검증해, 운에 덜 좌우되는 성능으로 모델 설정을 고르게 한다.
  • 테스트 데이터는 마지막에 한 번만 쓴다. 미래 정보·테스트 정보가 학습에 섞이는 데이터 누수를 경계하고, 너무 좋은 결과는 의심한다.
