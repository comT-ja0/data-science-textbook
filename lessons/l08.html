문제 정의수집전처리탐색모델링평가·해석공유
생각 열기 학교 데이터베이스에 학생 수천 명의 기록이 저장되어 있습니다. 담임 선생님은 “우리 반 학생 중 로봇공학반인 학생 명단”을, 도서부는 “동아리별 평균 독서 권수”를 원합니다. 매번 엑셀 파일을 열어 손으로 걸러 낼 수는 없겠죠. 데이터베이스에게 “이런 조건의 데이터를 보여 줘”라고 정확하게 부탁하는 말이 있다면 얼마나 편할까요? 그 말이 바로 SQL입니다.

1데이터베이스와 대화하는 언어, SQL 씨마스

SQL(Structured Query Language)은 관계형 데이터베이스에 데이터를 만들고, 넣고, 찾고, 고치고, 지우도록 요청하는 표준 언어입니다. ‘질의(query)’란 데이터베이스에 던지는 질문이라는 뜻입니다. SQL은 영어 문장과 비슷해서 읽기 쉽습니다.

잠깐 복습: 관계형 데이터베이스는 데이터를 테이블(행 = 레코드, 열 = 속성)에 저장하고, 각 행을 구별하는 기본키와 다른 테이블의 기본키를 가리키는 외래키로 테이블을 연결합니다.

데이터 정의어 (DDL)테이블의 구조를 만들고 바꾸고 없앤다.
CREATE · ALTER · DROP
데이터 조작어 (DML)테이블 안의 데이터를 넣고 찾고 고치고 지운다.
INSERT · SELECT · UPDATE · DELETE
데이터 제어어 (DCL)누가 데이터를 쓸 수 있는지 권한을 준다·빼앗는다.
GRANT · REVOKE

데이터를 다루는 네 가지 기본 동작을 CRUD(Create 생성, Read 읽기, Update 수정, Delete 삭제)라고 부르며, 각각 INSERT, SELECT, UPDATE, DELETE에 대응합니다. 이 차시에서는 파이썬에 들어 있는 작은 데이터베이스 SQLite(sqlite3 모듈)로 직접 실습합니다.

2테이블 만들고 데이터 넣기: CREATE · INSERT 씨마스

CREATE TABLE 동아리 (
    동아리코드 TEXT PRIMARY KEY,     -- 기본키
    동아리명   TEXT NOT NULL,         -- 비어 있으면 안 됨
    활동장소   TEXT
);
INSERT INTO 동아리 VALUES ('C1', '데이터탐구반', '정보실');

CREATE TABLE로 속성 이름과 자료형(TEXT 문자, INTEGER 정수, REAL 실수)을 정하고, PRIMARY KEY로 기본키를, REFERENCES로 외래키를 지정합니다. 아래 셀은 교재 데이터(school_clubs.csv, school_students.csv)를 SQLite 데이터베이스에 옮겨 담습니다. 외래키 규칙을 켜 두었기 때문에 동아리 테이블에 없는 코드는 데이터베이스가 거부합니다.

30명 중 서건우(20113, 코드 C9)의 입력이 FOREIGN KEY constraint failed로 거부되어 학생 테이블에는 29명이 들어갔습니다. 동아리코드가 비어 있는(NULL) 두 학생은 “아직 가입하지 않음”으로 허용됩니다. 이처럼 DBMS는 규칙을 어기는 데이터가 들어오는 것을 입구에서 막아 무결성을 지킵니다.

3원하는 데이터 꺼내기: SELECT 공통

SELECT 열 이름들          -- ③ 어떤 열을 보여 줄까?
FROM 테이블               -- ① 어느 테이블에서?
WHERE 조건                -- ② 어떤 행만?
GROUP BY 열               --    무엇을 기준으로 묶어 집계할까?
ORDER BY 열 ASC|DESC      -- ④ 어떤 순서로? (ASC 오름차순, DESC 내림차순)
LIMIT 개수;               -- ⑤ 몇 개까지?

SQL은 적는 순서와 실제 처리 순서가 다릅니다. 데이터베이스는 FROM → WHERE → GROUP BY → SELECT → ORDER BY → LIMIT 순으로 처리합니다. 아래 조립기에서 절을 하나씩 바꾸며 SQL 문과 결과가 어떻게 달라지는지 확인해 보세요.

4테이블 잇기와 데이터 고치기: JOIN · UPDATE · DELETE 씨마스

학생 테이블에는 동아리코드만 있으므로 동아리 이름을 보려면 두 테이블을 JOIN으로 연결합니다. ON 뒤에 연결할 키를 적습니다. JOIN(= INNER JOIN)은 양쪽에 짝이 있는 행만, LEFT JOIN은 왼쪽 테이블의 행을 모두 남깁니다.

세 테이블을 연결한 결과, 동아리별 1인당 독서 권수는 독서토론반 11.5권, 로봇공학반 10.0권, 방송반 9.8권, 데이터탐구반 7.3권, 환경지킴이 2.0권 순입니다. (데이터탐구반의 실제 값은 7.25권입니다. SQLite의 ROUND는 5를 올리고, pandas의 round는 가장 가까운 짝수 쪽으로 맞추므로 pandas에서는 7.2로 표시됩니다.) pandas의 merge로 하던 통합을 SQL 한 문장으로 한 것입니다(서건우 학생은 처음에 입력이 거부되어 이 집계에서 빠졌습니다).

학생은 다시 30명이 되었고, 독서 기록은 137건에서 20399의 기록 1건이 지워져 136건이 되었습니다.

WHERE 없는 UPDATE·DELETE는 위험하다 UPDATE와 DELETE는 WHERE 조건에 맞는 모든 행에 적용됩니다. 조건을 빠뜨리면 테이블 전체가 바뀌거나 지워집니다. 실제 업무에서는 먼저 같은 조건으로 SELECT를 실행해 바뀔 행을 확인한 뒤 UPDATE·DELETE를 실행하는 습관을 들입니다.
지도 팁 이 차시는 4학점 확장 차시로, 앞 차시(테이블 분해·통합)를 배우지 않았어도 2절의 복습 문단으로 따라올 수 있게 구성했습니다. 브라우저 셀 대신 온라인 SQL 실행기나 DB Browser for SQLite(무료 프로그램)를 써도 같은 SQL을 실습할 수 있습니다. 흔한 실수: 문자 값에 따옴표 빠뜨리기, = NULL로 빈 값 찾기(항상 결과 없음 → IS NULL), GROUP BY 없이 COUNT와 일반 열을 함께 SELECT 하기. 시간 배분: SQL 개념 8분 · CREATE/INSERT 10분 · 조립기 12분 · SELECT/JOIN 셀 12분 · UPDATE/DELETE와 정리 8분.

📌 핵심 정리

  • SQL은 관계형 데이터베이스에 질의하는 표준 언어로, 정의어(CREATE·ALTER·DROP), 조작어(INSERT·SELECT·UPDATE·DELETE), 제어어(GRANT·REVOKE)로 나뉜다.
  • SELECT … FROM … WHERE … GROUP BY … ORDER BY … LIMIT 순으로 쓰며, 처리는 FROM → WHERE → GROUP BY → SELECT → ORDER BY → LIMIT 순이다.
  • JOIN … ON 키로 여러 테이블을 연결해 통합된 결과를 얻는다. 빈 값은 IS NULL로 찾는다.
  • 기본키·외래키 규칙은 잘못된 데이터 입력을 막고, UPDATE·DELETE는 반드시 WHERE 조건을 확인한 뒤 실행한다.
