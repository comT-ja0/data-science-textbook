[12데과04-02] 수집된 데이터를 탐색적으로 분석하여 데이터 속 의미를 파악하고, 문제 해결을 위한 창의적인 방법을 구상한다.
문제 정의수집전처리탐색모델링평가·해석공유
생각 열기 요리사는 장을 봐 온 재료를 바로 냄비에 넣지 않습니다. 흙을 털고, 상한 잎을 떼고, 크기를 맞춰 썰어야 요리를 시작할 수 있죠. 그런데 상한 줄 알고 버린 잎이 사실은 원래 그런 색의 귀한 채소였다면? 데이터도 똑같습니다. 내려받은 데이터에는 빈칸, 잘못된 형식, 입력 실수가 섞여 있고, 그중에는 이상해 보이지만 사실은 가장 중요한 값도 숨어 있습니다. 오늘은 예시 프로젝트의 데이터를 모으고 다듬으면서, 무엇을 고치고 무엇을 지켜야 하는지 판단하는 연습을 합니다.

1공공 데이터 포털에서 수집하기 YBM

예시 프로젝트에는 두 종류의 데이터가 필요합니다. 학교의 일별 전력 사용량(행정실의 기록, 사용 허락 필요)과 같은 기간의 일평균기온입니다. 기온처럼 공공기관이 공개하는 데이터는 다음 절차로 수집합니다. 사이트 개편으로 메뉴 이름은 달라질 수 있으니, 핵심 흐름을 기억하세요.

순서할 일예: 기상청 기상자료개방포털(data.kma.go.kr)
1필요한 데이터를 제공하는 기관·포털을 찾는다.종합 포털인 공공데이터포털(data.go.kr)에서 ‘기온’으로 검색하면 기상청 자료로 연결된다.
2데이터 종류와 설명(메타데이터)을 읽는다.지상 관측 자료 중 ‘일자료’가 하루 단위 평균기온을 제공한다.
3조건(지역·기간·항목)을 선택한다.학교와 가장 가까운 관측 지점, 2025-03-01~2025-12-31, 평균기온
4파일 형식을 골라 내려받는다.CSV 형식으로 내려받는다. (일부 자료는 회원 가입이나 이용 신청이 필요하다.)
5출처·수집일·이용 조건을 기록한다.“기상청 기상자료개방포털, 2025-10-14 내려받음, 공공누리 출처 표시”
모둠 프로젝트용 데이터를 찾을 수 있는 곳 공공데이터포털(data.go.kr) · 국가통계포털 KOSIS(kosis.kr) · 기상자료개방포털(data.kma.go.kr) · 에어코리아(대기 질) · 각 시·도의 열린 데이터 광장(예: 서울 열린데이터광장) · 전력통계정보시스템 등. 원하는 데이터가 없으면 L44에서 설계한 설문·측정으로 직접 모읍니다.

두 파일을 내려받았다면 공통 속성(키)인 날짜로 연결해 하나의 표로 만듭니다(L07의 데이터 통합). 이 교재에서는 연결까지 마친 결과를 energy.csv(교육용 가상 데이터)로 제공합니다.

2파일 설계서 만들기 천재

분석을 시작하기 전에 각 속성이 무엇을 뜻하는지 정리한 파일 설계서(데이터 명세서, 메타데이터)를 만듭니다. 설계서가 있으면 “냉난방시간이 교실 전체의 합인가, 한 대의 가동 시간인가?” 같은 혼란을 막고, 값이 가능한 범위를 벗어났는지 판단하는 기준도 생깁니다.

3데이터 점검과 전처리 공통

전처리는 “눈에 띄는 것을 고치는 일”이 아니라 점검 → 판단 → 처리 → 기록의 순서로 진행합니다. 먼저 자료형, 빈칸, 가능한 범위(설계서 기준), 중복을 점검합니다.

빈칸과 범위 오류는 없습니다. 그런데 날짜의 자료형이 object(문자열)로 나옵니다. 문자열로는 요일을 구하거나 날짜 순으로 계산할 수 없으므로 날짜형으로 변환하고, 분석에 쓸 요일 속성을 새로 만듭니다. 또 ‘수업일’ 값이 학사 일정과 맞는지 교차 점검해 봅니다.

주말은 모두 수업일이 0이고, 평일에 수업이 없는 20일은 7~8월(여름 방학)에 몰려 있어 자연스럽습니다. 그런데 현충일·개천절·성탄절이 수업일 1로 기록되어 있고 전력 사용량도 수업일 수준입니다. 기록 자체는 서로 일관되지만 공휴일에 정규 수업을 했다는 것은 드문 일이므로, 이런 경우 행정실에 학사 일정을 확인해야 합니다. 이 교재에서는 “해당 학교가 그날 수업(또는 보충 수업)을 운영했다”고 확인했다고 보고 그대로 둡니다. 이 판단 역시 기록에 남깁니다.

이상치: 오류인가, 진짜인가?

이제 IQR 규칙(Q1 − 1.5×IQR 미만 또는 Q3 + 1.5×IQR 초과)으로 전력 사용량의 이상치를 찾아봅니다. 여기서 주의할 점이 있습니다. 이 데이터에는 수업일과 쉬는 날이라는 성격이 전혀 다른 두 집단이 섞여 있습니다.

전체를 한꺼번에 보면 이상치가 0건입니다. 두 집단이 섞여 사분위 범위가 넓어졌기 때문입니다. 집단별로 나누어 보면 11건이 걸리는데, 쉬는 날 1건(214kWh)을 빼면 모두 기온이 30℃를 넘거나 영하인 수업일이며 냉난방시간도 길었습니다. 즉 입력 실수가 아니라 냉난방이 실제로 많이 필요했던 날입니다. (쉬는 날의 214kWh도 유난히 적을 뿐 오류라는 근거가 없어 유지합니다.) 이런 값은 우리 질문(“언제 전기를 많이 쓰는가?”)의 핵심 정보이므로 지우지 않고 유지합니다. 통계 규칙은 이상치 후보를 알려 줄 뿐, 지울지 말지는 설계서·원자료·상식에 비추어 사람이 판단합니다.

energy.csv는 이미 연결·정리된 파일이지만, 여러분이 실제로 내려받는 원자료에는 훨씬 많은 문제가 있습니다. 아래 실험실은 전력 기록을 처음 받았을 때의 모습을 흉내 낸 원자료입니다. 문제가 있는 칸을 찾아 누르고 처리 방법을 고르면, 아래에 전처리 기록이 자동으로 쌓입니다.

관찰 포인트: 모든 ‘이상해 보이는 값’이 오류는 아닙니다. 파일 설계서의 범위와 그날의 상황(기온)을 함께 보고 판단하세요.

파이썬으로 전처리할 때도 같은 원칙을 지킵니다. 원본은 그대로 두고 복사본을 고치며, 무엇을, 왜, 몇 건 처리했는지 기록을 함께 남깁니다.

지도 팁 파이썬을 쓰지 않는 반은 스프레드시트의 찾기·바꾸기(쉼표 제거), 데이터 → 중복 항목 삭제, 필터로 범위 점검을 할 수 있고, Orange에서는 Impute(결측), Select Rows(범위), Edit Domain(형 변환) 위젯으로 같은 과정을 수행합니다. 흔한 오개념은 “이상치 = 지워야 할 값”입니다. 11건 중 10건이 실제 폭염·한파일이라는 점을 꼭 짚어 주세요. 모둠이 실제 포털에서 데이터를 받는 데 시간이 오래 걸리므로, 가능하면 전 차시 과제로 내려받기를 끝내 두게 합니다.

📌 핵심 정리

  • 공공 데이터는 기관·포털 찾기 → 설명 읽기 → 조건 선택 → 내려받기 → 출처·이용 조건 기록의 순서로 수집한다.
  • 파일 설계서(메타데이터)는 속성의 의미·자료형·단위·가능한 범위를 정리한 것으로, 오류 판단의 기준이 된다.
  • 전처리는 점검 → 판단 → 처리 → 기록의 순서로 하고, 원본은 덮어쓰지 않는다.
  • 성격이 다른 집단이 섞이면 이상치 판단이 달라진다. 통계적 이상치라도 실제 값이면 유지한다.
