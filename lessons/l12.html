생각 열기 학생회에서 “점심시간 매점 줄이 너무 길다”는 건의가 들어왔습니다. 학생회장은 일단 “데이터를 다 모아 보자!”라고 했습니다. 그런데 무엇을 모아야 할까요? 학생들의 키와 몸무게? 좋아하는 과자? 매점 결제 기록? 데이터는 많이 모은다고 좋은 것이 아니라, 문제에 답할 수 있는 데이터를 모아야 합니다. 오늘은 ‘무엇을, 어디서, 어떻게’ 모을지 정하는 법을 배웁니다.

1문제에서 출발하기: 가설과 필요한 데이터 씨마스 천재

데이터 수집은 문제 정의에서 시작합니다. 문제를 정했으면 “아마 이것 때문일 거야”라는 잠정적인 답, 즉 가설을 세웁니다. 가설에는 알고 싶은 결과에 해당하는 종속 변수와 그 결과에 영향을 줄 것 같은 독립 변수가 들어 있습니다. 두 변수를 측정할 데이터가 바로 우리가 모아야 할 데이터입니다.

가설종속 변수 (결과)독립 변수 (원인 후보)필요한 데이터
점심시간 시작 직후 10분에 결제가 몰려 줄이 길어진다.대기 시간시각(분 단위)시간대별 결제 건수, 대기 시간 측정값
계산대가 하나뿐이라 줄이 길어진다.대기 시간계산대 수, 1명 계산 시간계산대 운영 기록, 1명당 계산 시간 관찰
카드보다 현금 결제가 느려 줄이 길어진다.1명 계산 시간결제 수단결제 수단별 계산 소요 시간

이렇게 가설 표를 먼저 쓰면 필요 없는 데이터를 모으는 낭비와 꼭 필요한 데이터를 빠뜨리는 실수를 모두 줄일 수 있습니다.

2데이터를 모으는 방법 YBM

내가 직접 새로 만들어 모으는 데이터를 1차 데이터, 다른 기관이나 사람이 이미 모아 둔 데이터를 가져다 쓰는 것을 2차 데이터라고 합니다.

방법설명과 예장점 / 주의점
설문 조사질문지로 생각·경험을 묻는다. 예: 매점 이용 만족도 온라인 설문생각을 알 수 있음 / 응답자가 치우치기 쉽고 질문 표현에 따라 답이 달라짐
관찰·측정직접 보고 재고 기록한다. 예: 초시계로 1명당 계산 시간 재기정확함 / 시간과 노력이 많이 듦
센서·기기 기록기기가 자동으로 기록한다. 예: 교실 온도 센서, 결제 기록(POS), 스마트워치대량·연속 수집 / 기기 고장·오류 값 확인 필요
웹 수집 (API·크롤링)웹 사이트나 서비스에서 프로그램으로 가져온다. 예: 실시간 버스 도착 정보빠르고 최신 / 이용약관·개인정보 확인 필수
공공 데이터정부·공공 기관이 공개한 데이터. 예: 기상 관측, 인구, 대기 질신뢰도 높고 무료 / 원하는 지역·기간이 없을 수 있음
민간 데이터기업·단체가 공개하거나 판매하는 데이터. 예: 검색어 트렌드, 카드 소비 통계생활과 밀접 / 유료이거나 공개 범위가 제한됨

3공공·민간 데이터 포털 공통

데이터를 처음부터 직접 모으기 어렵다면 먼저 이미 공개된 데이터가 있는지 찾아봅니다. 대표적인 곳은 다음과 같습니다.

🏛️ 공공데이터포털 (data.go.kr)

중앙 행정 기관·지방 자치 단체·공공 기관의 데이터를 한곳에 모은 국가 포털. 파일 내려받기와 오픈 API를 모두 제공한다.

📈 국가통계포털 KOSIS (kosis.kr)

통계청이 운영. 인구·경제·교육·보건 등 국가 승인 통계를 표와 그래프로 제공한다.

🌤️ 기상자료개방포털 (data.kma.go.kr)

기상청이 운영. 지역별 기온·강수량·바람 등 관측 자료를 기간을 정해 내려받을 수 있다.

🏙️ 지방 자치 단체 열린 데이터

예: 서울 열린데이터광장. 공공자전거 대여 이력, 지하철 승하차 인원 등 도시 생활 데이터가 많다.

🔎 민간: 검색어 트렌드

포털 기업이 제공하는 검색어 추이 서비스(예: 네이버 데이터랩)로 사람들의 관심 변화를 볼 수 있다.

🌐 국제·커뮤니티

캐글(Kaggle) 같은 데이터 공유 커뮤니티, 세계은행·UN 통계 등 국제 기구의 공개 데이터.

필요한 데이터 고르기 — 문제마다 무엇을 모아야 할까?

4좋은 데이터의 조건 삼양

“쓰레기를 넣으면 쓰레기가 나온다(Garbage In, Garbage Out)”는 말이 있습니다. 분석 방법이 아무리 훌륭해도 데이터가 나쁘면 결과도 나쁩니다. 급식 잔반 사진으로 ‘잔반이 많은 날’을 알아내는 인공지능을 만든다고 생각하며 좋은 데이터의 조건을 살펴봅시다.

조건뜻잔반 사진 AI의 예
목적에 맞는가문제에 답하는 데 필요한 속성을 담고 있다.식판 사진과 함께 날짜·메뉴가 기록되어 있다.
양이 충분한가규칙을 찾을 만큼 개수가 많다.사진 30장이 아니라 여러 달 동안 수천 장
골고루 모였는가여러 경우가 치우치지 않게 포함되어 있다(대표성).한 반·한 메뉴가 아니라 여러 학년·여러 메뉴·여러 계절
시기가 알맞은가분석하려는 시기의 상황을 반영한다(최신성).급식 업체가 바뀌기 전 3년 전 사진만 쓰지 않는다.
분석 가능한 형태인가형식·단위가 일정하고 오류가 적다.같은 각도·밝기로 찍고, 흐린 사진은 걸러 낸다.
출처를 믿을 수 있는가누가, 언제, 어떻게 만들었는지 확인할 수 있다.수집 날짜·촬영자·방법을 기록해 둔다.

5메타데이터와 파일 설계서 천재

데이터를 모았다면 먼저 그 데이터가 어떻게 생겼는지 정리합니다. 데이터를 설명하는 데이터를 메타데이터라고 합니다. 출처, 수집 기간, 행(레코드) 수, 각 열(속성)의 이름·자료형·단위·결측 수·값의 범위 등을 표로 정리한 것을 파일 설계서(또는 데이터 명세서)라고 부릅니다. 공공데이터포털의 데이터에도 대부분 이런 설명이 함께 붙어 있습니다. 교재의 bike.csv(공공자전거 대여량, 가상 데이터)로 직접 만들어 봅시다.

설계서를 보면 bike.csv는 365개 레코드, 9개 속성이며 결측이 한 칸도 없습니다. ‘휴일’은 숫자(int64)로 저장되어 있지만 고유값이 0과 1 두 개뿐이라 사실은 범주형 속성임을 알 수 있습니다. 이처럼 자료형만 보지 말고 값의 의미까지 확인하는 것이 데이터 특성 분석의 첫걸음입니다.

지도 팁 공공데이터포털·KOSIS는 회원 가입 없이도 파일 내려받기가 가능한 자료가 많아 수업 중 탐색 활동에 적합합니다(오픈 API 인증키 발급은 가입이 필요하므로 L16 확장 차시에서 다룹니다). 비코딩 반은 스프레드시트에서 COUNTBLANK, MIN, MAX, COUNTA로 같은 메타데이터 표를 만들 수 있습니다. 흔한 오개념: “데이터는 많을수록 좋다” — 목적과 무관한 데이터, 특히 개인정보는 모으지 않는 것이 원칙임을 강조하세요.

📌 핵심 정리

  • 데이터 수집은 문제 정의 → 가설(종속·독립 변수) → 필요한 데이터 순서로 계획한다.
  • 수집 방법에는 설문·관찰·센서·웹 수집(1차·2차)과 공공·민간 데이터 포털 활용이 있다.
  • 좋은 데이터는 목적 적합·충분한 양·대표성·알맞은 시기·분석 가능한 형태·믿을 수 있는 출처를 갖춘다.
  • 메타데이터(파일 설계서)로 규모·자료형·결측·범위를 먼저 파악한다.
